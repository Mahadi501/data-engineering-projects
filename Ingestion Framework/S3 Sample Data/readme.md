# Purpose

Amazon S3 acts as the landing zone for source files generated by upstream systems.

Files are initially stored in the S3 landing bucket before being processed by the ingestion framework and loaded into Snowflake Bronze tables.

The S3 bucket serves as the first layer of the ingestion architecture and provides a durable, scalable, and cost-effective storage solution for incoming data files.

## S3 Object Metadata

Amazon S3 automatically stores metadata for each uploaded object.

The following metadata can be used by the ingestion framework and audit processes:

- **Key:** The unique file path and file name within the S3 bucket.
- **Size:** The size of the file in bytes.
- **Type:** The file format or content type of the uploaded object (e.g. CSV, JSON, Parquet).
- **Last Modified Date:** The timestamp indicating when the file was last uploaded or modified.
- **ETag:** An identifier associated with the uploaded file, commonly used to help identify duplicate files and support validation checks.

## Potential Usage Within the Ingestion Framework

The S3 metadata can be captured and stored within audit tables to provide ingestion traceability.

Examples include:

- **File Audit Table**
  - File Name
  - File Size
  - ETag
  - Arrival Timestamp

- **Load Execution Audit Table**
  - Source File Name
  - Processing Timestamp
  - Load Status

Capturing this information enables file tracking, duplicate detection, operational monitoring, and troubleshooting.
